# المراجعة الأمنية لـ BookFlow

هذا الملف هو **المرجع الثابت** لأي مراجعة أمنية للمشروع: شو بنفحص، وبأي ترتيب، وكيف بنسجّل النتائج.
كل مراجعة جديدة بتمشي على نفس القائمة، ونتائجها بتنكتب في **سجل المراجعات** آخر الملف، فما بيضيع إشي بين جلسة وجلسة.

## متى نعمل مراجعة؟

- قبل ما نبيع نسخة لزبون جديد أو نغيّر طريقة الاستضافة.
- بعد أي ميزة كبيرة بتلمس الحسابات أو الصلاحيات أو الحجز أو إرسال الرسائل (إيميل / واتساب / الذكاء الاصطناعي).
- وغير هيك: مرة كل 3 شهور.

## طريقة الشغل

1. **افتح جولة جديدة** في سجل المراجعات (رقم الجولة + التاريخ + آخر commit تم فحصه).
2. **امشِ على القائمة بالترتيب** (أ ← ح). كل بند إله "شو بنفحص" و"وين".
3. **كل مشكلة بتطلع = نتيجة** إلها رمز (`H-1`، `M-2`، `L-1`...) حسب الخطورة، وتنكتب في السجل وحالتها `مفتوحة`.
4. **كل نتيجة بتتصلح على branch لحالها** باسم `fix/...`، ومعها **اختبار** بيثبت إنها انسكّرت، ورسالة الـcommit بتبدأ بـ
   `fix(security H-1): ...`.
5. بعد الدمج: الحالة بتصير `مسكّرة` ومعها رقم الـcommit.
6. آخر الجولة: `npm test` في `server` و`client` كلهم لازم يمشوا، و`npm audit` بدون ثغرات.

## تصنيف الخطورة

| الرمز | الخطورة | معناها في BookFlow                                                                                              |
| ----- | ------- | ---------------------------------------------------------------------------------------------------------------- |
| `C-n` | حرجة    | حدا غريب بيوصل لبيانات أو حسابات مش إله، أو بيتحكم بالسيرفر. **بنوقف كل إشي وبنصلّحها.**                       |
| `H-n` | عالية   | إساءة استخدام سهلة بتضر بزنس أو زبون (تعبئة التقويم، إغراق إيميلات، تخطي حدود مهمة).                           |
| `M-n` | متوسطة  | بتحتاج ظروف خاصة، أو ضررها محدود (قفل حساب حدا، إعادة توجيه لموقع ثاني).                                       |
| `L-n` | منخفضة  | تقوية إضافية أو عدم تناسق بالقواعد، بدون ضرر عملي مباشر.                                                       |

الأرقام بتبدأ من 1 بكل جولة، والجولة نفسها بتنكتب في السجل (مثلاً: "الجولة 2 - H-1").

## القائمة

### أ. الأسرار والإعدادات

| شو بنفحص                                                                                                     | وين                                                    |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| ولا ملف `.env` ولا مفتاح حقيقي داخل الـrepo أو تاريخ git.                                                     | `git log -p` + `.gitignore`                            |
| `JWT_SECRET` و`SITE_PROXY_SECRET` و`JOBS_SECRET` طويلة (32+) والسيرفر بيرفض يشتغل بدونها أو لو قصيرة.         | `server/server.js`، `server/src/config/mode.js`        |
| `NODE_ENV` ناقص = إعدادات الإنتاج (كوكي HTTPS فقط، ما في token بالـJSON).                                      | `server/src/config/env.js`                             |
| الاختبارات ما بتلمس قاعدة البيانات الحقيقية (`MONGO_URI_TEST` فقط).                                           | `server/tests/helpers.js`                              |

### ب. تسجيل الدخول والحسابات

| شو بنفحص                                                                                                                 | وين                                                              |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| الـtoken بكوكي `httpOnly` + `Secure` + `SameSite=Lax`، وخوارزمية الـJWT ثابتة (HS256).                                    | `server/src/utils/authCookie.js`، `auth.middleware.js`           |
| تسجيل الخروج بيلغي الـtoken على السيرفر، وتغيير كلمة السر بيطلّع باقي الأجهزة.                                           | `auth.controller.js` (logout, changePassword)                    |
| حدود محاولات الدخول: لكل IP ولكل إيميل، وصاحب الحساب ما بينقفل من جهازه (known device).                                   | `rateLimit.middleware.js`، `utils/deviceCookie.js`               |
| نفس الجواب ونفس الوقت تقريباً سواء الإيميل مسجّل أو لا (login، forgot، register).                                         | `auth.controller.js`                                             |
| كود "نسيت كلمة السر" وكود تأكيد الإيميل: 6 أرقام، 5 محاولات، مدة قصيرة، مخزّن كـHMAC، وبيشتغل بس على الموقع الصح.          | `auth.controller.js`، `emailVerification.service.js`             |
| الدخول بخطوتين (2FA): الكود بيشتغل مرة وحدة، والكود الإيميلي ما بيتخطاه.                                                  | `utils/totp.js`، `auth.controller.js`                            |

### ج. الصلاحيات وعزل كل بزنس عن الثاني

| شو بنفحص                                                                                                         | وين                                                            |
| ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| كل route إله `protect` + `restrictTo` بالأدوار الصح (customer / staff / owner / superadmin).                      | `server/src/routes/*.js`                                       |
| كل استعلام على بيانات البزنس فيه `tenantId` من الحساب، مش من الطلب.                                               | كل الـcontrollers                                              |
| الموظف بيشوف ويعدّل مواعيده هو بس.                                                                                 | `appointment.controller.js` (`businessFilter`, `staffFor`)     |
| على السيرفر المشترك: كل موقع بيشوف بزنسه بس، وحساب زبون صالون A ما بيشتغل على B.                                  | `site.middleware.js`، `auth.middleware.js`                     |
| ما في route بيرجّع بيانات أكثر من اللازم (كلمات سر، hashes، أرقام كاملة للضيوف).                                  | الـDTOs بالـcontrollers                                        |

### د. الحجز وإساءة الاستخدام

| شو بنفحص                                                                                                           | وين                                                    |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| ما في حجز مزدوج لنفس الموظف بنفس الوقت (حتى مع طلبات متزامنة).                                                     | `booking.service.js` (`withStaffLock`)                 |
| حدود: لكل رقم ضيف، لكل حساب زبون، لكل بزنس باليوم، وأقصى عدد أيام لقدّام.                                          | `booking.service.js`، `public.controller.js`           |
| Turnstile على الحجز كضيف وعلى الروابط اللي بتبعت إيميلات.                                                          | `utils/turnstile.js`                                   |
| رابط "إدارة حجزي" عشوائي وطويل ومخزّن كـhash.                                                                      | `utils/manageToken.js`                                 |

### هـ. المدخلات

| شو بنفحص                                                                                                         | وين                                         |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| أي id من الطلب بيمر على `isId`، وأي نص على `isText` (حماية من NoSQL injection مثل `{"$gt": ""}`).                 | `utils/ids.js`، `auth.controller.js`        |
| التعديلات بتاخد حقول مسموحة بس (`pick`) - ما حدا بيقدر يغيّر `role` أو `tenantId`.                                 | `staff.controller.js`، `service.controller.js` |
| كل نص إله حد أقصى بالـmodel (`maxlength`).                                                                        | `server/src/models/*.js`                    |
| الإيميلات بتمرّر كل قيمة من المستخدم على `escapeHtml`.                                                           | `notify.service.js`                         |

### و. الواجهة (client)

| شو بنفحص                                                                                                     | وين                                       |
| ------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| CSP بـnonce جديد لكل صفحة، وheaders الأمان (منع الـiframe، HSTS، nosniff...).                                | `client/src/proxy.ts`، `next.config.ts`   |
| حماية CSRF: أي طلب بيغيّر إشي لازم يجي من نفس الموقع.                                                        | `client/src/proxy.ts` (`isCrossSite`)     |
| ما في `dangerouslySetInnerHTML`، وما في token أو بيانات حساسة بـ`localStorage`.                               | `grep` على `client/src`                   |
| إعادة التوجيه بعد الدخول بتروح لصفحات الموقع نفسه بس.                                                         | صفحة الـlogin                             |

### ز. الخدمات الخارجية

| شو بنفحص                                                                                       | وين                                  |
| ----------------------------------------------------------------------------------------------- | ------------------------------------ |
| سقف يومي للإيميلات (Brevo) وما في طريقة تتخطاه.                                                 | `notify.service.js`                  |
| واتساب التلقائي بيروح بس للي وافق، وللحجوزات المؤكدة.                                           | `reminder.service.js`                |
| مساعد Gemini: حد رسائل لكل IP ولكل بزنس باليوم، وما بيكشف تعليماته، وجوابه بيظهر كنص عادي.      | `assistant.service.js`               |

### ح. الاعتماديات والتشغيل

| شو بنفحص                                                                                                 | وين                                              |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `npm audit` في `server` و`client`: صفر ثغرات.                                                             | الترمنال                                         |
| عدّادات الـrate limit بقاعدة البيانات (ما بتتصفّر مع إعادة التشغيل).                                      | `utils/rateLimitStore.js`                        |
| رسائل الخطأ للمستخدم ما فيها stack أو تفاصيل داخلية.                                                     | `error.middleware.js`                            |
| النسخ الاحتياطي والاسترجاع شغّالين، وإيميل تنبيه عند أخطاء السيرفر.                                       | `npm run backup` / `restore`، `alert.service.js` |
