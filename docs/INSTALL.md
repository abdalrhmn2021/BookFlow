# دليل تركيب نسخة لزبون جديد

## الفكرة

```
                ┌─ laila-salon.vercel.app  (باسم ولوجو ولون صالون ليلى)
سيرفر واحد  ────┼─ reem-clinic.vercel.app  (باسم ولوجو ولون عيادة ريم)
+ قاعدة واحدة   └─ ...كل زبون جديد = موقع Vercel جديد فقط
```

- **سيرفر واحد مدفوع (7$ بالشهر) وقاعدة بيانات وحدة لكل زبائنك.** بتجهزهم **مرة وحدة بس** (الجزء أ).
- **كل زبون جديد = موقع Vercel مجاني** باسمه ولوجو ولونه، وسطر واحد في السيرفر (الجزء ب).
- بيانات كل زبون معزولة عن الثاني (هيك مبني BookFlow من الأول، وعليه اختبارات).
- ما حدا بيقدر يسجّل نشاط جديد على سيرفرك، ولا يشوف قائمة زبائنك.

> الديمو تبعك (`book-flow-eight.vercel.app`) بيضل زي ما هو على سيرفره المجاني - هذا سيرفر **منفصل** للزبائن.

---

## الجزء أ - مرة وحدة بس: سيرفر الزبائن

### أ1) قاعدة البيانات (MongoDB Atlas)

اعمل قاعدة بيانات جديدة للزبائن (منفصلة عن قاعدة الديمو). الأسهل: نفس الـ cluster بس **اسم قاعدة مختلف** في آخر الرابط:

`mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/bookflow-clients?retryWrites=true&w=majority`

تأكد أن **Network Access** فيه `0.0.0.0/0` (حتى يقدر Render يتصل).

> الخطة المجانية في Atlas إلها حد للمساحة - كافية بالبداية لعدد من الصالونات الصغيرة. لما يكبر عدد الزبائن راقب المساحة من لوحة Atlas.

### أ2) السيرفر (Render)

1. **New → Blueprint** واختر repo الـ BookFlow (بيقرأ `render.yaml`).
2. سمّي الخدمة مثلاً `bookflow-clients-api`.
3. عبّي المتغيرات:
   - `MONGO_URI` = رابط القاعدة من أ1
   - `CLIENT_URL` = اتركه مؤقتاً `https://example.com`
4. بعد الإنشاء، من **Environment** أضف:
   - `ALLOW_BUSINESS_SIGNUP` = `false`
   - `PUBLIC_DIRECTORY` = `false`
5. من **Settings → Instance Type** اختار أرخص خطة مدفوعة (**0.5 CPU / 512 MB - حوالي 7$ بالشهر**) حتى **ما ينام**.
6. انسخ رابط السيرفر، مثلاً `https://bookflow-clients-api.onrender.com`.
7. من **Environment** انسخ قيمة `PROXY_SECRET` (Render بيولّدها لحاله) - بتحطها في موقع كل زبون (ب2).

### أ3) الإيميلات: حجز جديد + نسيت كلمة المرور (اختياري، وأنصح فيه)

صاحب النشاط والموظف اللي انحجز عنده بيوصلهم إيميل فيه تفاصيل الحجز وزر يفتح المواعيد.
ونفس الإعداد بيشغّل **"نسيت كلمة المرور؟"** في صفحة الدخول (رابط صالح 30 دقيقة لمرة وحدة).
لوحة التحكم كمان بتنبّه بصوت وبطاقة "حجز جديد" وهي مفتوحة، بدون أي إعداد.

Render المجاني **بيمنع منافذ SMTP**، فالإيميل بيطلع عن طريق Brevo (مجاني لحد 300 إيميل باليوم):

1. اعمل حساب على [brevo.com](https://www.brevo.com).
2. **Senders** ← أضف إيميل المرسل وأكّده من الرسالة اللي بتوصلك (مثلاً إيميل خاص بخدمتك).
3. **SMTP & API** ← **API keys** ← أنشئ مفتاح وانسخه.
4. على Render ← **Environment** أضف:
   - `BREVO_API_KEY` = المفتاح
   - `MAIL_FROM` = الإيميل اللي أكّدته
   - `MAIL_FROM_NAME` (اختياري) = اسم يظهر كمرسل، والافتراضي اسم النشاط
5. اعمل حجز تجريبي وتأكد إن الإيميل وصل (شوف الـ Spam أول مرة).

> إيميل صاحب النشاط هو اللي دخلته بسكربت التجهيز، فتأكد إنه إيميل حقيقي بيقرأه.

**بدون Brevo:** "نسيت كلمة المرور؟" بيعطي رسالة إن الخدمة مش مفعّلة. لو صاحب النشاط نسي كلمة المرور،
غيّرها أنت من جهازك (على قاعدة الزبائن في `MONGO_URI`):

```bash
cd server
npm run reset-password -- --email laila@example.com
```

بيطلع لك كلمة مرور جديدة عشوائية تعطيها له، وبيطلع من حسابه على كل الأجهزة.

خلص الجزء أ. ما بترجعله إلا لتضيف رابط كل زبون في `CLIENT_URL`.

## الجزء ب - لكل زبون جديد (حوالي 20 دقيقة)

### ب0) اجمع من الزبون

| المعلومة | مثال | تُستخدم في |
|---|---|---|
| اسم النشاط بالعربي والإنجليزي | صالون ليلى / Laila Salon | `--name` و `BRAND_NAME_AR` و `BRAND_NAME` |
| رابط الحجز (slug) - إنجليزي صغير وأرقام وشرطات | `laila-salon` | `--slug` و `SINGLE_BUSINESS_SLUG` |
| اللوجو (PNG مربع أو SVG، خلفية شفافة أفضل) | `logo.png` | `BRAND_LOGO_URL` |
| اللون الأساسي (hex) | `#7c3aed` | `BRAND_COLOR` |
| اسم صاحب النشاط وإيميله ورقمه | ليلى - laila@example.com | سكربت التجهيز |
| الخدمات (اسم، سعر، مدة) والموظفين وساعات الدوام | قص شعر - 50 ₪ - 30 دقيقة | يدخلها صاحب النشاط من لوحة التحكم |
| المنطقة الزمنية لو مش فلسطين | `Asia/Riyadh` | `--timezone` |

> **مهم:** الزبون يحجز عند **موظف**. لو صاحب النشاط يشتغل لحاله (حلاق مثلاً)، لازم ينضاف كموظف كمان
> (بإيميل ثاني) حتى يظهر للحجز.

### ب1) شغّل سكربت التجهيز (من جهازك)

في `server/.env` حط `MONGO_URI` تبع **قاعدة الزبائن** (من أ1)، ثم:

```bash
cd server
npm run setup-client -- --name "صالون ليلى" --slug laila-salon --owner "ليلى" --email laila@example.com --phone 0599123456
```

- `--name` هو الاسم اللي بيظهر في **صفحة الحجز ورسائل التأكيد** - اكتبه باللغة اللي بيستخدمها زبائن النشاط.
- لو نسيت أي معلومة مطلوبة، السكربت بيسألك عنها.
- بدون `--password` بيطلع لك **كلمة مرور قوية عشوائية** - انسخها فوراً وأعطها لصاحب النشاط (ما بتنعرض مرة ثانية).
- لزبون خارج فلسطين أضف مثلاً `--timezone Asia/Riyadh`.
- **لا تشغّل** `npm run seed` على قاعدة الزبائن - هذا للديمو فقط.

بعد ما يخلص، **رجّع `MONGO_URI` في `server/.env` لقاعدتك أنت** حتى ما تشتغل بالغلط على بيانات الزبائن.

### ب2) موقع الزبون (Vercel)

1. **Add New → Project** واختر نفس الـ repo.
2. **Root Directory** = `client`.
3. اسم المشروع = اسم الزبون (هيك بيصير الرابط `laila-salon.vercel.app`).
4. **Environment Variables:**

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `API_URL` | `https://bookflow-clients-api.onrender.com` | سيرفر الزبائن من أ2، بدون `/api` في الآخر |
| `PROXY_SECRET` | نفس قيمة `PROXY_SECRET` على سيرفر الزبائن | **ضروري:** بدونه كل الزبائن بيتحسبوا كزائر واحد في حدود الحجز والدخول |
| `NEXT_PUBLIC_DEMO_MODE` | `false` | يخفي أزرار حسابات الديمو |
| `SINGLE_BUSINESS_SLUG` | `laila-salon` | نفس `--slug` بالضبط |
| `BRAND_NAME` | `Laila Salon` | |
| `BRAND_NAME_AR` | `صالون ليلى` | |
| `BRAND_COLOR` | `#7c3aed` | |
| `BRAND_LOGO_URL` | `/clients/laila-salon/logo.png` | انظر تحت |

**اللوجو** - طريقتين:
- حطه في الـ repo: `client/public/clients/laila-salon/logo.png` واعمل commit، والقيمة تصير `/clients/laila-salon/logo.png`.
- أو ارفعه على أي استضافة صور (Cloudinary مثلاً) وحط الرابط الكامل `https://...`.

5. **Deploy.**

> أي تعديل على متغيرات Vercel ما بيشتغل إلا بعد **Redeploy**.

### ب3) أضف رابط الزبون للسيرفر

Render ← سيرفر الزبائن ← **Environment** ← `CLIENT_URL`: أضف رابط الموقع الجديد **بفاصلة**:

```
https://laila-salon.vercel.app,https://reem-clinic.vercel.app
```

(أول زبون: بدّل `https://example.com` برابطه.) احفظ، وبيعيد التشغيل لحاله.

### ب4) جهّز النشاط مع صاحبه

ادخل بحساب صاحب النشاط (`/login`) ومن لوحة التحكم:

1. **الخدمات** - الأسماء والأسعار والمدد.
2. **الموظفين** - موظف واحد على الأقل.
3. **ساعات الدوام** - الافتراضي 9:00-17:00 والجمعة عطلة.

وانصحه يغيّر كلمة المرور لو أنت اللي اخترتها.

### ب5) افحص قبل التسليم

- [ ] الرابط الرئيسي `/` يفتح صفحة حجز النشاط مباشرة.
- [ ] الاسم واللوجو واللون صحيحين، بالعربي والإنجليزي.
- [ ] ما في "سجّل نشاطك" ولا "تصفح الأماكن" ولا أزرار ديمو.
- [ ] حجز تجريبي كضيف (اسم + رقم) يظهر في جدول لوحة التحكم.
- [ ] وصل إيميل "حجز جديد" لصاحب النشاط (لو فعّلت Brevo).
- [ ] الغِ الحجز التجريبي من لوحة التحكم.
- [ ] جرّب من الجوال.

## بعد التسليم

- **دومين خاص** (مثل `book.lailasalon.com`): من Vercel ← Settings ← Domains، وبعدها أضفه في `CLIENT_URL` على السيرفر.
- **التحديثات:** كل push على `main` بيتنشر تلقائياً على السيرفر **وكل مواقع الزبائن**. جرّب أي تعديل على نسختك أنت قبل ما تدمجه.
- **السعر للزبون:** السيرفر 7$ بالشهر لكل الزبائن مع بعض - اشتراك شهري بسيط من كل زبون بيغطيه ويزيد.
- **كل المواقع على سيرفر واحد:** لو وقع السيرفر بيوقع عند الكل - راقبه (Render بيبعتلك إيميل لو فشل).

## زبون بدو سيرفر خاص فيه (اختياري)

لزبون كبير بدو بياناته على سيرفر وقاعدة لحاله: اعمل له **قاعدة** و**سيرفر Render** جداد زي الجزء أ، بس بدل
`ALLOW_BUSINESS_SIGNUP` و `PUBLIC_DIRECTORY` حط على السيرفر `SINGLE_BUSINESS_SLUG=<slug تبعه>`. وكمّل الجزء ب
بس على قاعدته وسيرفره هو. التكلفة هون 7$ إضافية لهالزبون لحاله.

## مشاكل شائعة

| المشكلة | السبب الغالب |
|---|---|
| صفحة "النشاط غير موجود" | `SINGLE_BUSINESS_SLUG` على Vercel مش نفس `--slug`، أو شغّلت السكربت على قاعدة غير قاعدة الزبائن |
| الموقع ما بيجيب أي بيانات | `API_URL` على Vercel غلط (لازم رابط سيرفر الزبائن بدون `/api`) |
| اللون أو الاسم ما تغيّر | ما عملت Redeploy على Vercel بعد تعديل المتغيرات |
| اللوجو ما بيظهر | المسار غلط - لازم يبدأ بـ `/` لو الملف في `public`، أو `https://` لو رابط خارجي |
| "Too many bookings" أو "Too many login attempts" لزبائن مختلفين | `PROXY_SECRET` ناقص أو مختلف بين Render و Vercel |
| ما بيوصل إيميل الحجز الجديد | `BREVO_API_KEY` أو `MAIL_FROM` ناقص، أو إيميل المرسل مش مؤكَّد في Brevo - شوف Logs على Render (سطر `[notify]`) |
| رابط "نسيت كلمة المرور" بيفتح موقع غلط | رابط موقع الزبون ناقص من `CLIENT_URL` على سيرفر الزبائن (ب3) |
| صاحب نشاط بيدخل وبيطلع له "هذا الحساب تابع لمكان آخر" | بيدخل من موقع زبون ثاني - كل صاحب نشاط يدخل من موقعه هو |
| السكربت: `Email already exists` | الإيميل مستخدم عند زبون ثاني على نفس السيرفر - كل حساب لازم إيميل مختلف |
