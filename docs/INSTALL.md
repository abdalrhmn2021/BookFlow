# دليل تركيب نسخة لزبون جديد

كل الزبائن على **سيرفر واحد وقاعدة بيانات واحدة** (السيرفر المشترك)، وكل زبون له **موقع خاص فيه على Vercel**
باسمه ولوجو ولونه. الكود واحد (نفس الـ repo)، والذي يتغير بين زبون وآخر هو **متغيرات البيئة (env)** للموقع فقط.

```
موقع ليلى  (laila-salon.vercel.app)  ─┐
موقع أحمد  (ahmad-barber.vercel.app) ─┼──>  سيرفر BookFlow المشترك (Render)  ──>  قاعدة بيانات واحدة (Atlas)
موقع نور   (noor-clinic.vercel.app)  ─┘
```

كل موقع بيبعث للسيرفر مع كل طلب: **السر المشترك** (`SITE_PROXY_SECRET`) + **slug النشاط** تبعه.
السيرفر ما بيصدق الـ slug إلا لو السر صحيح، وكل موقع بيشوف نشاطه هو بس:
- صفحة الحجز والمواعيد المتاحة وقائمة الأنشطة.
- روابط "إدارة حجزي" للضيوف.
- تسجيل دخول صاحب النشاط وموظفيه ولوحة التحكم (صاحب صالون ليلى ما بيقدر يدخل من موقع أحمد).
- تسجيل نشاط جديد من الموقع **مقفول** - الزبائن الجدد بينضافوا بسكربت التجهيز فقط.

| | مرة وحدة بس | لكل زبون جديد |
|---|---|---|
| الخطوات | الجزء أ: قاعدة البيانات + السيرفر المشترك | الجزء ب: سكربت التجهيز + موقع Vercel |
| الوقت | حوالي 30 دقيقة | حوالي 10-15 دقيقة |

# الجزء أ - السيرفر المشترك (مرة وحدة)

## أ1) قاعدة البيانات (MongoDB Atlas)

اعمل **cluster منفصل** (أو مشروع Atlas جديد) لنسخ الزبائن، بعيد عن قاعدة الديمو.
مثال على الرابط (لاحظ اسم القاعدة `bookflow-clients` في آخره):

`mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/bookflow-clients?retryWrites=true&w=majority`

تأكد أن **Network Access** فيه `0.0.0.0/0` (حتى يقدر Render يتصل).

## أ2) السر المشترك

ولّد سر طويل مرة وحدة واحفظه عندك بمكان آمن - بتحتاجه لكل موقع زبون:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> لا تحطه في الـ repo ولا تبعته لحدا. لو انكشف، غيّره على السيرفر وعلى كل المواقع.

## أ3) السيرفر (Render)

1. **New → Blueprint** واختر repo الـ BookFlow (بيقرأ `render.yaml`).
2. سمّي الخدمة مثلاً `bookflow-clients-api`.
3. **اختار خطة مدفوعة** (مش Free) - المجانية بتنام بعد 15 دقيقة، وأول زبون بعدها بيستنى حوالي 50 ثانية.
4. عبّي المتغيرات:

| المتغير | القيمة |
|---|---|
| `MONGO_URI` | رابط القاعدة من أ1 |
| `SHARED_SERVER` | `true` |
| `SITE_PROXY_SECRET` | السر من أ2 (أو اترك Render يولّده وانسخه من **Environment**) |
| `CLIENT_URL` | روابط مواقع الزبائن **مفصولة بفاصلة** - بتضيف رابط كل زبون جديد (ب3). روابط الإيميلات بتفتح منها |

> **لا تحط** `SINGLE_BUSINESS_SLUG` على السيرفر المشترك - السيرفر بيرفض يشتغل لو الاثنين موجودين.

5. انسخ رابط السيرفر، مثلاً `https://bookflow-clients-api.onrender.com`.
6. افتح الرابط بالمتصفح - لازم يظهر `BookFlow API is running`.

## أ4) الإيميلات: حجز جديد + نسيت كلمة المرور (اختياري، وأنصح فيه)

صاحب النشاط والموظف اللي انحجز عنده بيوصلهم إيميل فيه تفاصيل الحجز وزر يفتح المواعيد.
ونفس الإعداد بيشغّل **"نسيت كلمة المرور؟"** في صفحة الدخول (رابط صالح 30 دقيقة لمرة وحدة).
لوحة التحكم كمان بتنبّه بصوت وبطاقة "حجز جديد" وهي مفتوحة، بدون أي إعداد.

Render المجاني **بيمنع منافذ SMTP**، فالإيميل بيطلع عن طريق Brevo (مجاني لحد 300 إيميل باليوم):

1. اعمل حساب على [brevo.com](https://www.brevo.com).
2. **Senders** ← أضف إيميل المرسل وأكّده من الرسالة اللي بتوصلك (مثلاً إيميل خاص بخدمتك).
3. **SMTP & API** ← **API keys** ← أنشئ مفتاح وانسخه.
4. على Render ← **Environment** أضف:
   - `BREVO_API_KEY` = المفتاح
   - `MAIL_FROM` = الإيميل اللي أكّدته
   - `MAIL_FROM_NAME` (اختياري) = اسم يظهر كمرسل، والافتراضي اسم النشاط
5. اعمل حجز تجريبي وتأكد إن الإيميل وصل (شوف الـ Spam أول مرة).

> إيميل صاحب النشاط هو اللي دخلته بسكربت التجهيز، فتأكد إنه إيميل حقيقي بيقرأه.

**بدون Brevo:** "نسيت كلمة المرور؟" بيعطي رسالة إن الخدمة مش مفعّلة. لو صاحب النشاط نسي كلمة المرور،
غيّرها أنت من جهازك (على قاعدة الزبائن في `MONGO_URI`):

```bash
cd server
npm run reset-password -- --email laila@example.com
```

بيطلع لك كلمة مرور جديدة عشوائية تعطيها له، وبيطلع من حسابه على كل الأجهزة.

## أ5) تذكير واتساب تلقائي قبل الموعد (اختياري - ممكن تبيعه كإضافة مدفوعة)

السيرفر بيبعت لكل زبون رسالة واتساب قبل موعده بـ 24 ساعة، **من رقم واتساب بزنس واحد إلك** لكل الصالونات،
والرسالة فيها اسم الصالون. بيشتغل عن طريق **WhatsApp Cloud API** من Meta.

> **التكلفة:** Meta بتحاسب على كل رسالة تذكير (فئة Utility)، والسعر بيختلف حسب دولة الزبون - شوف صفحة أسعار
> WhatsApp Business على موقع Meta قبل ما تحدد سعر الإضافة للزبون. هيك التذكير **مطفي افتراضياً** وبتشغّله لكل زبون لحاله.

### مرة وحدة: جهّز حساب Meta

أسماء الأزرار ممكن تختلف شوي، Meta بتغيّر الواجهة كثير:

1. اعمل **Meta Business Account** على business.facebook.com (يفضّل توثّقه - التوثيق بيرفع حد الرسائل اليومي).
2. على developers.facebook.com: **Create App** ← نوع **Business** ← أضف منتج **WhatsApp**.
3. أضف **رقم تلفون** للبزنس - رقم **مش مستخدم** على تطبيق واتساب العادي. انسخ **Phone number ID** تبعه.
4. **توكن دائم:** Business Settings ← **System users** ← أضف System user بصلاحية Admin ← **Generate token**،
   اختار التطبيق، وعلّم على `whatsapp_business_messaging` و `whatsapp_business_management`.
   (التوكن المؤقت اللي بيطلع بصفحة التجربة بيخلص بعد 24 ساعة - لا تستخدمه.)
5. **قالب الرسالة:** WhatsApp Manager ← **Message templates** ← **Create template**:
   - الفئة: **Utility** - الاسم: `booking_reminder` - اللغة: **Arabic**
   - النص (لازم **4 متغيرات بنفس الترتيب**: الزبون، النشاط، الخدمة، الموعد):

   ```
   مرحباً {{1}}، نذكّرك بموعدك في {{2}} لخدمة {{3}} يوم {{4}}.
   للإلغاء أو تغيير الموعد تواصل معنا. نراك قريباً!
   ```

   - ابعته للمراجعة واستنى لحد ما يصير **Approved** (عادة دقائق لساعات).

### مرة وحدة: على السيرفر (Render ← Environment)

| المتغير | القيمة |
|---|---|
| `WHATSAPP_TOKEN` | التوكن الدائم من خطوة 4 |
| `WHATSAPP_PHONE_NUMBER_ID` | من خطوة 3 |
| `WHATSAPP_TEMPLATE` | `booking_reminder` (اسم القالب بالضبط) |
| `WHATSAPP_TEMPLATE_LANG` | `ar` |

احفظ. بالـ Logs لازم يطلع سطر `[reminder] automatic WhatsApp reminders every 10 min`.

> **على خطة Render المجانية** السيرفر بينام، فالمؤقت الداخلي بيوقف. وقتها استخدم cron خارجي مجاني (مثل cron-job.org)
> يعمل كل 10 دقائق: `POST https://<سيرفرك>.onrender.com/api/jobs/reminders` مع header اسمه `x-jobs-secret`
> وقيمته `JOBS_SECRET` من Environment على Render. الطريقتين مع بعض آمنين - ما في زبون بيوصله تذكيرين.

### لكل زبون: شغّل التذكير

- زبون جديد: أضف `--whatsapp` لأمر سكربت التجهيز (ب1). ولو زبائنه من دولة ثانية: `--country-code 966` مثلاً.
- زبون موجود: من **لوحة الإدارة** (`/admin`) علّم على **تذكير واتساب** عند النشاط.

بلوحة التحكم، تحت الحجز اللي انبعتله تذكير، بيطلع "أُرسل تذكير واتساب تلقائي الساعة ...".
وزر التذكير اليدوي بيضل موجود - وأي حجز ذكّرته يدوياً ما بيوصله تذكير تلقائي.

## أ5ب) مساعد الحجز الذكي (اختياري - ممكن تبيعه كإضافة)

شات بصفحة الحجز بيجاوب الزبائن عن الخدمات والأسعار ومواعيد العمل **والأوقات الفاضية الحقيقية** (بيفحص الجدول).
ما بيحجز ولا بيلغي - بيوجّه الزبون لنموذج الحجز بنفس الصفحة. بيرد بلغة الزبون (عربي أو إنجليزي).

**مرة وحدة (Render ← Environment):**

| المتغير | القيمة |
|---|---|
| `GEMINI_API_KEY` | مفتاح من [Google AI Studio](https://aistudio.google.com/apikey) (فيه خطة مجانية) |
| `GEMINI_MODEL` | فاضي = `gemini-3.5-flash-lite` (سريع ورخيص) |

**لكل زبون:** من `/admin` علّم على **مساعد الحجز الذكي** عند النشاط. بدون علامة ما بيظهر الشات.

- كل رسالة = طلب على مفتاحك. في حد 20 رسالة كل 15 دقيقة لكل زائر عشان ما حدا يستنزف المفتاح.
- المحادثة **ما بتنحفظ** على السيرفر. سياسة الخصوصية بتذكر إن الرسائل بتروح لـ Google.
- بالخطة المجانية، Google ممكن تستخدم الرسائل لتحسين نماذجها - لزبائن كبار فعّل الدفع (Billing) على المفتاح.

## أ6) لوحة الإدارة إلك (`/admin`)

صفحة سرية إلك بس كصاحب الخدمة، فيها **كل زبائنك على السيرفر**: صاحب كل نشاط وتلفونه، وعدد الموظفين،
والحجوزات آخر 30 يوم، والحجوزات الجاية، وآخر حجز. يعني بتعرف مين شغّال فعلاً ومين ما بيستخدم النظام.

ومنها بتعمل:
- **إيقاف / تفعيل** أي نشاط، مثلاً لو ما دفع.
- **تذكير واتساب** تشغيل أو إطفاء لكل نشاط (أ5).
- **الباقة**، و**مدفوع حتى** (تاريخ)، و**ملاحظة** إلك. لما يفوت التاريخ بيطلع على النشاط **"متأخر بالدفع"**، بس **ما بيوقف لحاله**، إنت بتقرر.

**مرة وحدة:** اعمل حسابك من جهازك (مع `MONGO_URI` تبع قاعدة الزبائن بـ `server/.env`):

```bash
cd server
npm run create-admin -- --email you@example.com --name "اسمك"
```

بيطلعلك كلمة سر قوية، احفظها. بعدها ادخل من **أي موقع من مواقعك** على `/login` بهالحساب، وبيفتحلك `/admin` لحاله.
ما في أي طريقة تعمل حساب مدير من الموقع - بس هالأمر.

# الجزء ب - زبون جديد (كل مرة)

## ب0) اجمع من الزبون قبل ما تبدأ

| المعلومة | مثال | تُستخدم في |
|---|---|---|
| اسم النشاط بالعربي والإنجليزي | صالون ليلى / Laila Salon | `BRAND_NAME_AR` و `BRAND_NAME` |
| رابط الحجز (slug) - إنجليزي صغير وأرقام وشرطات | `laila-salon` | السكربت + `SINGLE_BUSINESS_SLUG` |
| اللوجو (PNG مربع أو SVG، خلفية شفافة أفضل) | `logo.png` | `BRAND_LOGO_URL` |
| اللون الأساسي (hex) | `#7c3aed` | `BRAND_COLOR` |
| صورة للمشاركة 1200×630 (اختياري) - مثلاً تصميم فيه اللوجو | `share.png` | `BRAND_SHARE_IMAGE_URL` |
| اسم صاحب النشاط وإيميله ورقمه | ليلى - laila@example.com | سكربت التجهيز |
| الخدمات (اسم، سعر، مدة) والموظفين وساعات الدوام | قص شعر - 50 ₪ - 30 دقيقة | يدخلها صاحب النشاط من لوحة التحكم |
| المنطقة الزمنية لو مش فلسطين | `Asia/Riyadh` | `--timezone` |

> **مهم:** الزبون يحجز عند **موظف**. لو صاحب النشاط يشتغل لحاله (حلاق مثلاً)، لازم ينضاف كموظف كمان
> (بإيميل ثاني) حتى يظهر للحجز.
>
> **إيميل صاحب النشاط لازم يكون جديد على السيرفر كله** (ما بينفع نفس الإيميل يكون صاحب نشاطين).
> أما **عملاء** كل صالون فمنفصلين: نفس الشخص بيقدر يسجّل عند صالونين بنفس الإيميل، وبيصير إله حساب منفصل عند كل واحد.

## ب1) شغّل سكربت التجهيز (من جهازك)

في `server/.env` حط رابط **قاعدة الزبائن المشتركة** في `MONGO_URI` و `SHARED_SERVER=true`، ثم:

```bash
cd server
npm run setup-client -- --name "Laila Salon" --slug laila-salon --owner "Laila" --email laila@example.com --phone 0599123456
```

- لو نسيت أي معلومة مطلوبة، السكربت بيسألك عنها.
- بدون `--password` بيطلع لك **كلمة مرور قوية عشوائية** - انسخها فوراً وأعطها لصاحب النشاط (ما بتنعرض مرة ثانية).
- لزبون خارج فلسطين أضف مثلاً `--timezone Asia/Riyadh`.
- لو صاحب النشاط **بيشتغل بنفسه** (حلاق لحاله مثلاً) أضف `--owner-books`: الزبائن بيقدروا يحجزوا عنده مباشرة بدون ما تضيف موظف. وبيقدر يشغّلها أو يطفيها بعدين من تبويب الموظفين ("أستقبل حجوزات أيضاً").
- **لا تشغّل** `npm run seed` على قاعدة الزبائن - هذا للديمو فقط، وبيضيف نشاط وحسابات ديمو بكلمات سر معروفة.

بعد ما يخلص، **رجّع `MONGO_URI` في `server/.env` لقاعدتك أنت** حتى ما تشتغل بالغلط على بيانات الزبائن.

> السيرفر المشترك بيعرف الزبون الجديد لحاله أول ما موقعه يبعث الـ slug تبعه - التعديل الوحيد على السيرفر هو إضافة رابط موقعه لـ `CLIENT_URL` (ب3).

## ب2) موقع الزبون (Vercel)

1. **Add New → Project** واختر نفس الـ repo.
2. **Root Directory** = `client`.
3. اسم المشروع = اسم الزبون (هيك بيصير الرابط `laila-salon.vercel.app`).
4. **Environment Variables:**

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `API_URL` | `https://bookflow-clients-api.onrender.com` | رابط السيرفر المشترك، بدون `/api` في الآخر - نفسه لكل الزبائن |
| `SITE_PROXY_SECRET` | السر من أ2 (أو اترك Render يولّده وانسخه من **Environment**) | **نفس** القيمة اللي على Render بالضبط - وبدون `NEXT_PUBLIC_` |
| `SINGLE_BUSINESS_SLUG` | `laila-salon` | **نفس** الـ slug اللي أعطيته للسكربت |
| `NEXT_PUBLIC_DEMO_MODE` | `false` | يخفي أزرار حسابات الديمو |
| `BRAND_NAME` | `Laila Salon` | |
| `BRAND_NAME_AR` | `صالون ليلى` | |
| `BRAND_COLOR` | `#7c3aed` | |
| `BRAND_LOGO_URL` | `/clients/laila-salon/logo.png` | انظر تحت |
| `BRAND_SHARE_IMAGE_URL` | `/clients/laila-salon/share.png` | اختياري: الصورة اللي بتظهر لما ينشر رابط الموقع على فيسبوك وواتساب، 1200×630. فاضي = صورة عامة "احجز موعدك أونلاين" بدون أي اسم |
| `SITE_URL` | `https://laila-salon.com` | اختياري: فقط لو للزبون دومين خاص مش مضاف في Vercel. فاضي = دومين Vercel |

**اللوجو** - طريقتين:
- حطه في الـ repo: `client/public/clients/laila-salon/logo.png` واعمل commit، والقيمة تصير `/clients/laila-salon/logo.png`.
- أو ارفعه على أي استضافة صور (Cloudinary مثلاً) وحط الرابط الكامل `https://...`.

5. **Deploy.**

> أي تعديل على متغيرات Vercel ما بيشتغل إلا بعد **Redeploy**.

## ب3) أضف رابط الموقع للسيرفر

Render ← سيرفر الزبائن ← **Environment** ← `CLIENT_URL`: أضف رابط الموقع الجديد **بفاصلة**، واحفظ (بيعيد التشغيل لحاله):

```
https://laila-salon.vercel.app,https://ahmad-barber.vercel.app
```

هيك زر إيميل "حجز جديد" ورابط "نسيت كلمة المرور" بيفتحوا موقع **نفس الزبون**. لو نسيت هالخطوة، الروابط بتفتح أول موقع بالقائمة.

## ب4) جهّز النشاط مع صاحبه

ادخل بحساب صاحب النشاط **من موقعه هو** (`laila-salon.vercel.app/login`) ومن لوحة التحكم:

1. **الخدمات** - الأسماء والأسعار والمدد.
2. **الموظفين** - موظف واحد على الأقل، **أو** صاحب النشاط يفعّل "أستقبل حجوزات أيضاً" على بطاقته (أول بطاقة في تبويب الموظفين) إذا بيخدم الزبائن بنفسه.
3. **ساعات الدوام** - الافتراضي 9:00-17:00 والجمعة عطلة.

وانصحه يغيّر كلمة المرور لو أنت اللي اخترتها.

## ب5) افحص قبل التسليم

- [ ] الرابط الرئيسي `/` يفتح صفحة حجز النشاط مباشرة.
- [ ] الاسم واللوجو واللون صحيحين، بالعربي والإنجليزي.
- [ ] ما في "سجّل نشاطك" ولا "تصفح الأماكن" ولا أزرار ديمو.

## سياسة الخصوصية والشروط

كل موقع فيه صفحتين: `/privacy` (سياسة الخصوصية) و `/terms` (شروط الاستخدام)، بالعربي والإنجليزي، ورابطهم بأسفل كل صفحة
وتحت زر الحجز والتسجيل. النص بياخد اسم النشاط لحاله، وانت بتضيف على **كل موقع زبون** (Vercel):

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `OPERATOR_NAME` | `عبد الرحمن الكحلوت` | مشغّل النظام - بيظهر بسياسة الخصوصية |
| `OPERATOR_EMAIL` | إيميل الدعم تبعك | لطلبات الزبائن عن بياناتهم - حط إيميل عمل مش إيميل شخصي |
| `DATA_RETENTION_MONTHS` | `12` | **نفس** القيمة اللي على السيرفر (Render) |

- **موافقة واتساب:** بنموذج الحجز في خيار "أرسل لي تذكيراً على واتساب" **مش مؤشّر افتراضياً**. التذكير التلقائي بيروح **بس** للي أشّروا عليه - هيك بتطلب سياسة Meta. وبحجز التلفون/الحضور من لوحة التحكم، صاحب النشاط بيأشّر عليه إذا الزبون وافق.
- **مدة الاحتفاظ:** بعد `DATA_RETENTION_MONTHS` شهر من الموعد، اسم الضيف ورقمه وملاحظاته بينمحوا لحالهم (الموعد بيضل للإحصائيات).
- **حذف الحساب:** الزبون بيحذف حسابه بنفسه من صفحة "مواعيدي".
- **تسليم بيانات الزبون:** من `/admin` ← **تصدير البيانات** - ملف JSON فيه الخدمات والموظفين والزبائن والمواعيد (بدون كلمات سر).
- Meta بتطلب **رابط سياسة الخصوصية** لما تفعّل واتساب API - استخدم `https://<موقعك>/privacy`.

> النصوص مكتوبة بحيث توصف شو النظام بيعمل فعلاً، بس **مش استشارة قانونية**. قبل عملاء كبار خلّي محامي يراجعها مع العقد مرة وحدة.

## بعد التسليم

- **دومين خاص** (مثل `book.lailasalon.com`): من Vercel ← Settings ← Domains، وبعدها أضفه لـ `CLIENT_URL` على السيرفر.
- **التحديثات:** كل push على `main` بيتنشر تلقائياً على **السيرفر المشترك وكل مواقع الزبائن**. جرّب أي تعديل على نسختك أنت قبل ما تدمجه.
- **إيقاف زبون ما دفع:** من **لوحة الإدارة** (`/admin`) ← **إيقاف**. موقعه بيصير "غير موجود" وصاحبه وموظفينه ما بيقدروا يدخلوا. **تفعيل** بيرجّعه زي ما كان، وما بيضيع ولا حجز.
- **النسخ الاحتياطي:** كل الزبائن بقاعدة وحدة، ففعّل النسخ الاحتياطي (Backups) على الـ cluster.

## الحجوزات اللي ما حدا أكّدها

حجز ضل **"بانتظار التأكيد"** وفات وقته: صاحب النشاط بيقدر يعلّمه **تم** أو **لم يحضر** من الجدول.
ولو ما حدا عمل شي، بعد **24 ساعة** من نهاية الموعد بيتسكر لحاله كـ"ملغي - ما تأكد" (بتغيّرها بـ `PENDING_AUTO_CLOSE_HOURS`).

## مشاكل شائعة

| المشكلة | السبب الغالب |
|---|---|
| صفحة "النشاط غير موجود" | `SITE_PROXY_SECRET` على Vercel مختلف عن Render (أو ناقص)، أو `SINGLE_BUSINESS_SLUG` مش نفس الـ slug بالسكربت، أو ما عملت Redeploy |
| "هذا الحساب تابع لنشاط آخر" عند الدخول | صاحب النشاط بيدخل من موقع زبون ثاني - لازم يدخل من موقعه هو |
| الموقع ما بيجيب أي بيانات | `API_URL` على Vercel غلط (لازم رابط Render بدون `/api`) |
| السيرفر ما بيشتغل على Render (بالـ Logs) | `SHARED_SERVER=true` بدون `SITE_PROXY_SECRET`، أو السر أقصر من 32 حرف، أو `SINGLE_BUSINESS_SLUG` موجود مع `SHARED_SERVER` |
| اللون أو الاسم ما تغيّر | ما عملت Redeploy على Vercel بعد تعديل المتغيرات |
| اللوجو ما بيظهر | المسار غلط - لازم يبدأ بـ `/` لو الملف في `public`، أو `https://` لو رابط خارجي |
| "Too many bookings" أو "Too many login attempts" لزبائن مختلفين | `SITE_PROXY_SECRET` ناقص على Vercel أو مختلف عن Render |
| ما بيوصل إيميل الحجز الجديد | `BREVO_API_KEY` أو `MAIL_FROM` ناقص، أو إيميل المرسل مش مؤكَّد في Brevo - شوف Logs على Render (سطر `[notify]`) |
| ما بيوصل تذكير واتساب | القالب مش Approved، أو اسمه/لغته مش نفس `WHATSAPP_TEMPLATE`/`WHATSAPP_TEMPLATE_LANG`، أو تذكير واتساب مطفي للنشاط بلوحة الإدارة، أو التوكن مؤقت وخلص - شوف Logs (سطر `[reminder]`) |
| زر الإيميل أو رابط "نسيت كلمة المرور" بيفتح موقع زبون ثاني | رابط موقع الزبون ناقص من `CLIENT_URL` على السيرفر (ب3) |
| السكربت: `Email already exists` | الإيميل مستخدم لصاحب نشاط ثاني أو موظف على السيرفر - استخدم إيميل ثاني |
| `npm run reset-password` بيقول إن للإيميل أكثر من حساب | عميل مسجّل عند أكثر من صالون - أضف `--business <slug>` للحساب اللي بدك إياه |
| السكربت: `This business URL is already taken` | الـ slug محجوز لزبون ثاني - اختار غيره |

## ملحق: زبون كبير على سيرفر خاص فيه

لو زبون بده سيرفر وقاعدة لحاله (بيانات منفصلة تماماً): اعمل Blueprint جديد على Render بقاعدة جديدة،
وبدل `SHARED_SERVER` حط `SINGLE_BUSINESS_SLUG=laila-salon` على السيرفر **وعلى** الموقع (نفس القيمة)،
وشغّل سكربت التجهيز على قاعدته هو. باقي الخطوات نفسها.
